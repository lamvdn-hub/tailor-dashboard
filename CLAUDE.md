# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page CRM/operations tool for a tailor shop: clients, body measurements, garment orders ("sessions"), fabric stock, a task list, inbound customer queries, and a public order-tracking page. Frontend-only React app; all persistence, auth and file storage is Supabase, accessed directly from the browser with the anon key (no API layer of our own).

Stack: React 18 + TypeScript, Vite, React Router v7, Tailwind v3 (`darkMode: 'class'`), lucide-react icons, `@supabase/supabase-js`. Originally scaffolded with Bolt (`.bolt/prompt`: no extra UI/icon packages; lucide only).

## Commands

```bash
npm install
npm run dev          # Vite dev server
npm run build        # production build (no typecheck step)
npm run typecheck    # tsc --noEmit -p tsconfig.app.json
npm run lint         # eslint .
npm run preview
npm run test:gdpr    # node tests/gdpr-compliance-check.js — hits a live Supabase project
```

There is no unit-test framework. `tests/` contains GDPR deletion checks that run against a real Supabase instance and need `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` in the environment; `tests/deletion-verification.sql` is run manually in the Supabase SQL editor.

Env (`.env`, see `.env.example`): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, optional `VITE_APP_URL` (base for auth email redirects). Missing vars do not crash — `src/lib/supabase.ts` falls back to a placeholder URL and logs an error.

Deploy target is static hosting with SPA fallback (`netlify.toml` and `public/_redirects` both rewrite `/*` → `/index.html`; required for PKCE password-reset callbacks).

## Architecture

### Routing and auth (`src/App.tsx`)
- Two route trees chosen by pathname: an unauthenticated tree (`/login`, `/signup`, `/password-reset`, `/update-password`, `/privacy-policy`, `/terms-of-service`, `/status/:token`) and everything else wrapped in `ProtectedRoute` + `ProtectedLayout` (top `Navigation` + `<main>`). Adding a public route requires updating the `isAuthPage`/`isPublicPage` checks, not just adding a `<Route>`.
- `AuthContext` wraps Supabase auth (PKCE, session in localStorage under `tailor-notebook-auth`). Signup is gated by the `is_email_whitelisted` RPC against an `email_whitelist` table; on signup all consent types are recorded as granted. Login/logout write audit log rows.
- `PasswordRecoveryHandler` redirects to `/update-password` on a `PASSWORD_RECOVERY` auth event or recovery tokens in the URL hash.

### Data model (Supabase, `supabase/migrations/`)
Migrations are Bolt-generated and include duplicates/re-applies (e.g. `create_tasks_table` and `restructure_measurements_table` appear more than once); read the latest-dated file for a table's current shape.
- `clients` — `name` (denormalised "First Last", still required) plus `first_name`, `last_name`, `phone`, `email`. UI prefers `first_name last_name`, falls back to `name`.
- `sessions` — an order. `service_type` (`MTM`|`Bespoke`), `garment_type` (`jacket`|`trousers`|`suit`), `fabric_id`, `status`, free-text notes (`style_notes`, `client_requests`, `adjustment_remarks`; suits use `jacket_notes`/`trousers_notes` instead of `style_notes`), suit config (`suit_type`, `lapel_type`, `button_type`, `vent_type`), `display_id` + `display_id_normalized`, and `status_token` (auto-generated by DB trigger).
- `measurement_definitions` — seeded catalogue of jacket/trousers measurements, each `mode` `single` or `paired`, ordered by `order_index`.
- `measurements` — one row per value: `session_id`, `measurement_definition_id`, `section`, `unit_cm`, and `measurement_name`. **Paired measurements are stored as two rows whose names are suffixed ` (L)` / ` (R)`**; most read paths match on `measurement_name` rather than the definition id, so this naming convention is load-bearing.
- `session_photos` + storage bucket `session_photos` — path `${sessionId}/${ts}_${uuid}.jpg` and `thumb_…` sibling; displayed via 1-hour signed URLs.
- `fabrics` (`status` `in`|`out`), `tasks` (category/priority/status are capitalised string enums, optional `client_id`/`session_id`), `problems` (the "Queries" page; inbound support requests written by an external source, with a capitalised `Status` boolean column).
- GDPR tables: `user_profiles` (incl. `shop_code`), `audit_logs` (+ trigger-based logging), `consent_types`/`user_consents` (`record_user_consent` RPC), retention policy functions (`apply_all_retention_policies`, meant to be scheduled externally), `delete_user_account` RPC (removes the user's PII, keeps business data).
- RLS is "any authenticated user can do anything" on business tables: there is no per-user or per-shop ownership column. It is effectively one shared workspace.

### Order status workflow
Status options depend on `service_type`: MTM → `active → fitting → pickup → completed`; Bespoke → `active → fitting_1 → fitting_2 → pickup → completed`. This mapping is duplicated in `Dashboard.tsx`, `SessionDetail.tsx` and `OrderStatus.tsx`, and the Dashboard also normalises legacy status strings (`ready`, `ready for pickup`, …). Change all of them together.

### Display IDs
`src/lib/displayIdUtils.ts` builds `SHOPCODE-YYMMDD-NNN` client-side: shop code from the current user's `user_profiles.shop_code` (default `SHP`), sequence = count of sessions created today + 1. Not concurrency-safe.

### Measurement entry — two paths that must stay in sync
1. **Form entry** (`NewSession.tsx`, `SessionDetail.tsx`, `MeasurementTable`): table driven by `measurement_definitions`; can prefill from the client's most recent session ("Load from Latest Measurements").
2. **Guided entry** (`VisualMeasurements.tsx`, `BodyDiagram`): SVG body diagram with hotspot points from `src/lib/bodyMeasurements.ts` (coordinates, instructions, plausible min/max for out-of-range warnings). `src/lib/garmentMeasurementMapping.ts` maps each diagram point to one or more `measurement_definitions` by **definition name + section** — renaming a definition breaks the mapping silently.
   - For a new order, guided entry runs in "draft mode": the unsaved session form and draft measurements travel through React Router `location.state` between `/sessions/new` and `/sessions/new/body-measurements`, and the session row is only inserted when saved from the diagram page. A page refresh loses the draft.
   - For an existing session (`/sessions/:id/body-measurements`) each value is written immediately.
`src/lib/measurementCategories.ts` is a third, older name list used only to filter "load latest" results by fuzzy substring match.

### Public order tracking
`/status/:token` (`OrderStatus.tsx`) queries `sessions` by `status_token` with the anon client and shows a timeline plus hard-coded `SHOP_INFO`. It only works if anon has SELECT on `sessions`/`clients`. Staff copy the link from the session detail page.

### Search
`GlobalSearchResults` fans out `ilike` queries to clients, sessions (garment type only — not display ID), fabrics, tasks and problems; user input is interpolated directly into PostgREST `.or()` filter strings.

### UI conventions
- Shared primitives in `src/components/` (`Button`, `Card`, `Input`, `Select`, `Textarea`, `Table`, several bespoke status/priority dropdowns, `MobileSelect`). Toasts via `useToast` + `<ToastContainer>` rendered per page; Tasks/Queries use `alert()` and an ARIA live region instead.
- Theme: `ThemeContext` (`light`|`dark`|`system`, persisted to `localStorage.theme`) plus an inline script in `index.html` that applies `dark` before first paint. Brand colour `#506B4D` is hard-coded across files rather than in Tailwind config; font is Lora (Google Fonts).
- Dates render as `en-GB` via `src/lib/dateUtils.ts`.
- Fabrics, Queries and Reports routes exist but are commented out of the nav; Reports is a placeholder.
